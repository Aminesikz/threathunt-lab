# ThreatHunt Lab

A small Python lab for practising threat hunting and detection engineering on
synthetic Windows and Linux process-creation events.

The use case is suspicious **PowerShell** activity. It follows these steps:
hypothesis → hunt → detection → testing → evaluation. Events use ECS
(Elastic Common Schema) field names, so the queries and rules carry over to
Elastic Security, but you don't need an Elastic cluster to run anything here.

## What's in the repo

```text
src/threathunt_lab/   Python code: loading, validation, hunt, detection, evaluation
data/synthetic/       Windows and Linux events + their labels (kept in separate files), PHP server list
docs/                 Event schema, PHP2Shell research
hunts/                H001 (PowerShell) and H002 (PHP2Shell) hunt write-ups
detections/           D001 and D002: Sigma rules, write-ups and a Linux ECS pipeline
reports/              Evaluation results (generated by the evaluate command)
tests/                pytest tests
```

## Setup

Python 3.11+.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
```

## Usage

Check that the dataset is valid:

```bash
.venv/bin/python -m threathunt_lab validate
```

Run the threat hunt (steps Q1–Q7, or one step with `--step Q4`):

```bash
.venv/bin/python -m threathunt_lab hunt
```

Check the Sigma rule and convert it to an Elastic EQL query:

```bash
.venv/bin/sigma check detections/sigma/powershell_encoded_or_download_cradle.yml
.venv/bin/sigma convert -t eql -p ecs_windows detections/sigma/powershell_encoded_or_download_cradle.yml
```

Run detection D001 on the events and compare with the labels. This writes
`reports/evaluation.json` and `reports/evaluation.md`:

```bash
.venv/bin/python -m threathunt_lab evaluate
```

Check a server list for PHP versions affected by PHP2Shell:

```bash
.venv/bin/python -m threathunt_lab php-versions
```

Run the PHP2Shell hunt on the Linux events, and convert detection D002:

```bash
.venv/bin/python -m threathunt_lab hunt --hunt H002
.venv/bin/sigma convert -t eql -p detections/pipelines/ecs_linux.yml detections/sigma/php_web_server_starts_shell.yml
```

Run the tests:

```bash
.venv/bin/python -m pytest
```

## Results

On the 16 test events, detection D001 had **no false positives** and missed
**one** event (a renamed copy of PowerShell, because the data has no original
file name). See [`reports/evaluation.md`](reports/evaluation.md).

## Notes

- **Labels are separate from events.** The hunt and the detection only see the
  events, never the expected answers.
- **No `malicious` label.** Events are `benign` or `suspicious_looking`, which
  describes how a test scenario was designed, not proof of an attack.
- **Limits.** 16 hand-made events can't show how common this activity is in real
  networks. The Elastic queries have been checked against Elastic's docs and
  sigma-cli, but haven't been run on a real cluster. The rule was built from
  the same events it's tested on, so the evaluation results are optimistic.

## Safety

All data is synthetic and inert. Never run command lines taken from the events.
See [`data/README.md`](data/README.md).
